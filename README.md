## Реализованная структура (паттерн MVC)

### Model (работа с данными)
- `config/database.js` — конфигурация подключения к MySQL через Sequelize ORM.
- `models/recipe.js` — модель рецепта с полями: `id`, `name`, `difficulty` (ENUM: easy/medium/hard), `cooking_time_min`, `createdAt`, `updatedAt`.
- `models/ingredient.js` — модель ингредиента с полями: `id`, `name`, `quantity`, `recipe_id`.
- `models/index.js` — инициализация моделей и настройка связи «один-ко-многим» (Recipe.hasMany / Ingredient.belongsTo) с каскадным удалением.

### Controller (бизнес-логика)
- `controllers/recipeController.js` — обработчики CRUD-операций с валидацией входных данных и обработкой ошибок.

### View (маршруты API)
- `routes/recipeRoutes.js` — маршруты Express, делегирующие запросы контроллеру.
- `app.js` — точка входа, синхронизация БД и запуск сервера.

## Реализованные возможности

### CRUD-операции
- **GET /api/recipes** — получение списка рецептов с фильтрацией и сортировкой.
- **GET /api/recipes/:id** — получение одного рецепта по ID с ингредиентами.
- **POST /api/recipes** — создание рецепта с одновременным добавлением ингредиентов.
- **PUT /api/recipes/:id** — частичное обновление полей рецепта.
- **DELETE /api/recipes/:id** — удаление рецепта (каскадно удаляются ингредиенты).

### Валидация данных
- Проверка обязательных полей (`name`, `difficulty`, `cooking_time_min`).
- Валидация сложности через белый список: `['easy', 'medium', 'hard']`.
- Проверка `cooking_time_min` на положительное число.
- Возврат статуса **400 Bad Request** с понятным сообщением при нарушении правил.

### Фильтрация и сортировка
- Query-параметр `?difficulty=hard` фильтрует рецепты по сложности.
- Query-параметр `?order=desc` меняет направление сортировки (по умолчанию — ASC).
- Сортировка по полю `cooking_time_min` (от быстрого к долгому или наоборот).

### Связи между таблицами
- Один рецепт может иметь множество ингредиентов (one-to-many).
- При удалении рецепта автоматически удаляются связанные ингредиенты (`onDelete: 'CASCADE'`).
- Метод `include: [Ingredient]` подгружает ингредиенты в одном запросе (JOIN).

### ORM Sequelize
- Автоматическая синхронизация схемы БД (`sequelize.sync()`).
- Защита от SQL-инъекций через параметризованные запросы.
- Валидация на уровне модели (`allowNull`, `validate`, `ENUM`).
- Абстракция от конкретной СУБД — при необходимости можно переключиться на PostgreSQL или SQLite изменением одного файла конфигурации.

### Обработка ошибок
- **400** — невалидные входные данные (неизвестная сложность, отсутствие обязательных полей).
- **404** — рецепт не найден по ID.
- **500** — внутренние ошибки сервера с логированием в консоль.
- Блоки `try...catch` во всех асинхронных обработчиках.

## Логика работы приложения

### При запуске сервера
1. Загружается конфигурация БД из `config/database.js`.
2. Инициализируются модели и устанавливаются связи между ними.
3. Sequelize синхронизирует схему (создаёт таблицы `recipes` и `recipe_ingredients`, если их нет).
4. Подключаются маршруты по пути `/api/recipes`.
5. Сервер начинает слушать порт 3000.

### Создание рецепта (POST)
1. Контроллер извлекает из тела запроса поля `name`, `difficulty`, `cooking_time_min`, `ingredients`.
2. Проходит валидация: проверка обязательности, типа данных, допустимых значений сложности.
3. Создаётся запись в таблице `recipes` через `Recipe.create()`.
4. Если передан массив `ingredients`, через `Ingredient.bulkCreate()` массово создаются связанные записи с `recipe_id`.
5. Возвращается полный объект рецепта с вложенными ингредиентами (статус 201 Created).

### Получение списка (GET)
1. Из query-параметров извлекаются `difficulty` и `order`.
2. Формируется объект `where` для фильтрации (если сложность указана и валидна).
3. Определяется направление сортировки: `ASC` по умолчанию, `DESC` при `order=desc`.
4. Выполняется запрос `Recipe.findAll()` с `include: [Ingredient]` и `order`.
5. Возвращается JSON с количеством записей, параметрами сортировки и массивом данных.

### Обновление рецепта (PUT)
1. Ищется рецепт по ID; если не найден — возвращается 404.
2. Валидируется поле `difficulty`, если оно передано.
3. Формируется объект обновления только из переданных полей (через spread-оператор с проверкой на `undefined`).
4. Вызывается `recipe.update()` — Sequelize генерирует `UPDATE` только для изменённых колонок.
5. Возвращается обновлённый объект.

### Удаление рецепта (DELETE)
1. Ищется рецепт по ID; если не найден — возвращается 404.
2. Вызывается `recipe.destroy()` — Sequelize удаляет запись и, благодаря `CASCADE`, все связанные ингредиенты.
3. Возвращается сообщение об успешном удалении.

## Инструменты и технологии

- **Node.js** — среда выполнения JavaScript.
- **Express** — веб-фреймворк для маршрутизации и обработки HTTP-запросов.
- **Sequelize** — ORM для работы с реляционными базами данных.
- **MySQL** — реляционная СУБД (драйвер `mysql2`).
- **Postman** — инструмент для тестирования API-запросов.
- **MySQL Workbench** — графический клиент для проверки данных в БД.
- **npm** — менеджер пакетов для установки зависимостей.
- **nodemon** — утилита для автоматического перезапуска сервера при разработке.
